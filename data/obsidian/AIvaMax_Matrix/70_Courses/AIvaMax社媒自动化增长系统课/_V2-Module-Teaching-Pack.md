# AIvaMax V2 Module Teaching Pack

## Purpose

This pack upgrades the course from outline-level modules to recording-ready teaching material. It should be used by the instructor before filling slides, workbooks, and assessments.

## Global Teaching Rule

Public lessons teach decision models, worksheets, review gates, and examples. Operational execution details stay in internal SOPs unless they have passed risk review and brand rewrite.

## Module 01 - Social Automation Growth Map

### Teaching Goal

Help students understand the complete AIvaMax growth system: project input, account matrix, platform weighting, content system, engagement workflow, review, and delivery pack.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Explain the growth system as a workflow, not a tool trick | Draw the flow from intake to review |
| 5-15 min | Separate strategy, content, execution, and review | Use one sample product and mark each layer |
| 15-25 min | Show why account, platform, and content decisions must be made together | Compare weak plan vs structured plan |
| 25-35 min | Introduce review gates and public/private boundaries | Mark which details are public course vs internal SOP |
| 35-45 min | Convert the full system into a project checklist | Have students complete the checklist |

### Workbook Task

Students write a one-page growth map for a product using four blocks: audience, channel, content, and review.

### Assessment

The student passes if the map has a clear goal, one primary audience, one primary platform, one content pillar, one review metric, and one risk gate.

### Production Output

`AIvaMax Growth System Map`

## Module 02 - Project Intake And Diagnosis

### Teaching Goal

Teach students to collect enough project information before proposing channels, content, or execution.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Bad inputs create bad growth plans | Show a vague brief and identify missing fields |
| 5-15 min | Diagnose product, audience, market, proof, assets, and goal | Walk through the intake schema |
| 15-25 min | Convert customer pain into content and CTA direction | Build a pain-to-content table |
| 25-35 min | Score readiness: offer, proof, assets, compliance, tracking | Use red/yellow/green readiness labels |
| 35-45 min | Decide whether the project is ready for a 7, 14, 30, 60, or 90 day cycle | Choose a cycle based on evidence |

### Workbook Task

Students complete the project intake table for one product and mark missing information.

### Assessment

The diagnosis must include target audience, pain points, buying motivation, available assets, primary goal, and launch constraints.

### Production Output

`Project Intake And Diagnosis Sheet`

## Module 03 - Account Matrix Design

### Teaching Goal

Teach students to design account roles instead of using identical accounts for identical actions.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Account matrix means role design | Explain brand, expert, product, community, support, proof roles |
| 5-15 min | Match roles to content jobs | Map each role to content type and audience stage |
| 15-25 min | Choose lightweight, standard, or extended matrix | Use project size and duration as the decision rule |
| 25-35 min | Define ownership and review | Add owner and review column to the matrix |
| 35-45 min | Turn the matrix into weekly workload | Convert roles into content and review tasks |

### Workbook Task

Students design a 30-day account matrix with role, platform, content job, owner, and risk level.

### Assessment

The matrix must avoid duplicate roles, show clear content differentiation, and include a manual review owner.

### Production Output

`Account Matrix Sheet`

## Module 04 - Platform Selection And Weighting

### Teaching Goal

Teach students to choose platforms by audience behavior, content format, trust path, and conversion path.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Platform choice is resource allocation | Show why "post everywhere" fails |
| 5-15 min | Define each platform's job | Map platforms to awareness, trust, community, search, and conversion |
| 15-25 min | Apply industry weight patterns | Compare SaaS, ecommerce, local service, education, and AI tools |
| 25-35 min | Convert weights into content and review workload | Translate percentages into weekly effort |
| 35-45 min | Set one primary and one secondary platform | Require a decision, not a generic list |

### Workbook Task

Students build a platform weight table with rationale, content format, CTA, and review dependency.

### Assessment

The plan passes if platform weights add to 100%, each platform has a distinct job, and the primary platform matches audience behavior.

### Production Output

`Platform Weight Table`

## Module 05 - Task Type Library

### Teaching Goal

Teach students to select task families by goal and risk level rather than treating all actions as equal.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Task library is a menu, not a mandate | Split tasks into publish, discover, engage, follow-up, monitor |
| 5-15 min | Match tasks to marketing goals | Build a goal-to-task matrix |
| 15-25 min | Add stage logic | Show how cold start, growth, conversion, and review stages differ |
| 25-35 min | Add risk labeling | Mark high-risk communication tasks |
| 35-45 min | Choose a small task set for one project | Limit the plan to what can be reviewed |

### Workbook Task

Students select 6-10 task families for one campaign and mark goal, stage, platform, owner, and risk level.

### Assessment

The selected tasks must support the primary goal, avoid unnecessary complexity, and identify review triggers.

### Production Output

`Goal-To-Task Library Selection`

## Module 06 - 7/14/30/60/90 Day Growth Rhythm

### Teaching Goal

Teach students to stage growth work into cycles with clear outputs and review gates.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Different cycles answer different questions | Explain test, validate, standardize, expand, productize |
| 5-15 min | 7-day cycle tests readiness and angles | Build a Day 1-7 plan |
| 15-25 min | 14 and 30-day cycles test repeatability | Show platform, content, and lead-signal checkpoints |
| 25-35 min | 60 and 90-day cycles build assets and SOPs | Convert winning actions into reusable assets |
| 35-45 min | Create the next review decision | Decide continue, adjust, pause, or scale |

### Workbook Task

Students choose one cycle and create a day-by-day or phase-by-phase plan with outputs and review gates.

### Assessment

The plan must include a cycle goal, phase outputs, review date, owner, and criteria for scaling or stopping.

### Production Output

`Growth Rhythm Plan`

## Module 07 - Content System And Calendar

### Teaching Goal

Teach students to build a content system from audience pain, platform format, trust path, and CTA.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Content calendar starts from jobs, not dates | Define content jobs: educate, prove, compare, invite, answer |
| 5-15 min | Build content pillars from pain points | Convert intake pain into five content pillars |
| 15-25 min | Match content formats to platforms | Map short post, thread, carousel, video, article, FAQ |
| 25-35 min | Build a weekly rhythm | Create a 5-day content calendar |
| 35-45 min | Add review and claim strength | Label claims as observed, estimated, or illustrative |

### Workbook Task

Students produce a 2-week calendar with platform, topic, format, CTA, asset needed, and review owner.

### Assessment

The calendar passes if it has varied content jobs, platform-fit formats, clear CTA, and no unsupported claims.

### Production Output

`Content Calendar And Topic Bank`

## Module 08 - Comments, Messages, And Lead Conversion

### Teaching Goal

Teach students to turn interactions into qualified next steps without using aggressive or context-free communication.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Lead conversion starts with context | Define qualified interaction |
| 5-15 min | Comment replies should add value before asking | Rewrite a generic reply into a helpful reply |
| 15-25 min | Messages require consent, relevance, and human review | Show approval criteria |
| 25-35 min | Build a lead signal table | Score interest, fit, urgency, and next step |
| 35-45 min | Route leads to a human-owned follow-up | Define owner and response SLA |

### Workbook Task

Students rewrite three risky messages into optional, context-aware, human-approved follow-up messages.

### Assessment

The rewritten communication must be specific to context, low pressure, opt-in, and assigned to a review owner.

### Production Output

`Lead Conversion Review Sheet`

## Module 09 - Campaign Naming And Structure

### Teaching Goal

Teach students to make naming and campaign structure searchable, auditable, and reusable.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Bad names destroy review and reuse | Show ambiguous names and their failure modes |
| 5-15 min | Explain the AIvaMax naming pattern | Break down client, platform, goal, stage, week, owner |
| 15-25 min | Map names to campaign, account group, task, and calendar | Build the hierarchy |
| 25-35 min | Add version and review status | Show draft, approved, active, paused, archived |
| 35-45 min | Rename a messy campaign set | Students apply the naming standard |

### Workbook Task

Students create names for one campaign, three account groups, five content items, and five review tasks.

### Assessment

Names must identify platform, goal, stage, time period, and owner without opening the file.

### Production Output

`Campaign Naming And Structure Sheet`

## Module 10 - Data Review And Forecasting

### Teaching Goal

Teach students to use data for decisions without turning forecasts into promises.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Forecasts are planning ranges | Explain conservative, expected, and upside ranges |
| 5-15 min | Separate activity, response, lead signal, and conversion readiness | Build the review table |
| 15-25 min | Use assumptions explicitly | Show content volume, response rate, signal rate, risk adjustment |
| 25-35 min | Decide what to scale or stop | Use a sample weekly review |
| 35-45 min | Write the next-week operating priority | Force one clear priority |

### Workbook Task

Students complete a weekly review table and write a three-scenario forecast.

### Assessment

The forecast must include assumptions, ranges, risk adjustment, and a next action.

### Production Output

`Weekly Review And Forecast Sheet`

## Module 11 - Risk Boundaries And Human Review

### Teaching Goal

Teach students to separate automation-friendly work from human-owned decisions and sensitive communication.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Risk boundary is part of the product | Explain why review increases quality |
| 5-15 min | Mark public, internal, client, and sales-preview versions | Use the audience versioning matrix |
| 15-25 min | Identify red flags | Review unsupported claims, impersonation, context-free messaging |
| 25-35 min | Add release gates | Define review owner, evidence, rewrite, approval |
| 35-45 min | Audit one module or client deliverable | Students mark what must be rewritten |

### Workbook Task

Students audit a draft campaign and label each item as public-safe, internal-only, client-ready, or blocked.

### Assessment

The audit must catch sensitive communication, unsupported claims, source exposure, and missing owners.

### Production Output

`Risk Boundary Audit`

## Module 12 - Client Delivery Pack Generation

### Teaching Goal

Teach students to convert the course factory into a client-facing delivery pack without exposing internal source material.

### Lesson Flow

| Segment | Teaching point | Instructor action |
| --- | --- | --- |
| 0-5 min | Delivery pack is the productized output | Show pack structure |
| 5-15 min | Convert intake into project summary | Fill the client brief |
| 15-25 min | Attach account, platform, content, rhythm, review, and risk assets | Build pack table of contents |
| 25-35 min | Remove internal-only material | Apply audience versioning |
| 35-45 min | Create a handoff checklist | Assign client and AIvaMax owners |

### Workbook Task

Students assemble a client pack with seven sections: brief, strategy, account matrix, platform weights, calendar, forecast, and risk boundary.

### Assessment

The pack passes if it is client-readable, source-safe, action-oriented, and scoped to the agreed campaign duration.

### Production Output

`Client Delivery Pack`
