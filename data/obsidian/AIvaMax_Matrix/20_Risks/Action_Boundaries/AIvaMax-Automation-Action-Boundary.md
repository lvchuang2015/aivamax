# AIvaMax Automation Action Boundary

## Purpose

This boundary note defines what can be taught publicly, what can be used internally, and what requires manual review before entering any client-facing asset.

## Boundary Matrix

| Area | Public course | Internal SOP | Client delivery |
| --- | --- | --- | --- |
| Account strategy | Allowed as method and worksheet | Allowed with project details | Allowed after client review |
| Platform weighting | Allowed as decision model | Allowed with evidence links | Allowed as recommendation |
| Content calendar | Allowed as template | Allowed with channel details | Allowed with dates and owners |
| Engagement workflow | Allowed as relationship framework | Allowed with task controls | Allowed as reviewed workflow |
| Comment templates | Teach principles only | Store rewritten examples | Use only after approval |
| Message templates | Teach consent, context, and review | Store rewritten examples | Use only after approval |
| Performance forecast | Allowed as range model | Allowed with assumptions | Allowed with disclaimer |

## Red Flags

- Any promise of guaranteed reach, leads, sales, or platform outcome.
- Any copy that feels deceptive, impersonated, or context-free.
- Any workflow that removes human review from sensitive communication.
- Any public material exposing internal source references or private file paths.
- Any client asset that cannot explain its assumptions.

## Release Gate

A lesson, SOP, or client pack is releasable only when it has:

- clear visibility label,
- source traceability kept internally,
- brand-safe wording,
- risk rewrite for sensitive communication,
- owner approval.
