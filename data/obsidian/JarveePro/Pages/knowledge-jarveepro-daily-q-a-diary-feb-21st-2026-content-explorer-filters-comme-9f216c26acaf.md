2026-02-21

Introduction

Today’s Q&A covers three important operational topics for power users and agencies:

Filtering disabled accounts inside Content Explorer

Understanding how comment limits per run actually work

Clarifying the meaning of “Max Uses Per Item” in repost campaigns

If you’re running multiple VPS + Monitor setups, these settings matter more than you think.

Q1: Can you add a filter in Content Explorer to filter accounts by status (active, disabled, etc.) so we can remove disabled accounts from scraper results?

Answer:

Yes.

The requested filter for account status (Active / Disabled) has been added to Content Explorer.

This allows users to quickly filter and remove disabled accounts from scraped lists, improving data quality and reducing campaign waste.

Q2: Is “Max Uses Per Item” the number of times the repost source account can be used? If so, should it be set higher than 1? How does the program know to run just one post per run?

“Max Uses Per Item” refers to how many times a specific source item (such as a repost source post/account) can be used by the campaign.

If you set it to 1, the source will only be used once.

If you want it reused multiple times, you should increase that number.

As for how the program determines what to execute per run:

Execution behavior is automatic and based on campaign settings, limits, and available eligible items. The system processes what is allowed within the configured limits during each run cycle.

For more details about campaign settings:

http://blog.jarveepro.com/knowledge/JarveePro-Campaign-Settings/Shared-Campaign-Settings-Explained/5451

Q3: Is “Comments Allowed Per Post” a total lifetime limit or per-run limit?

Answer:

It functions per run, not as a permanent lifetime cap.

This means if you leave the tool running, it can provide that amount during each execution cycle unless additional limits are configured.

Q4: Why did one post receive all 9 comments in a single run? There is no limit per run setting.

The number of comments per run is calculated as:

Total Posts × Comments Per Post

If no stricter rate limits are applied, the system will execute everything allowed within the configured parameters in a single run.

There is no separate “comments per run” toggle — the output volume is determined by:

Number of target posts

Comments allowed per post

Account rate limits

Q5: How can I control comment volume more precisely?

Use the

Rate Limit settings

to limit comments per account.

This allows you to control how aggressively each account operates, preventing large bursts in a single run.

Running fewer accounts simultaneously can also reduce output intensity.

Reference:

http://blog.jarveepro.com/knowledge/JarveePro-Updates/JarveePro-Rate-Limits-Avoid-Bans-with-Safe-Daily-Activity/5521

Summary

Today’s key clarifications:

Account status filtering is now available in Content Explorer.

“Max Uses Per Item” controls how many times a source item can be reused.

Comment limits are calculated per run, not lifetime totals.

Output volume is determined by campaign math (Posts × Comments Per Post).

Rate limits are the real control lever for pacing automation.

For advanced users managing multiple VPS environments, understanding execution math is critical for safe scaling.
